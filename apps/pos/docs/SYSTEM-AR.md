# تعريف السيستم — InnoForge POS

ملف تعريفي لأي حد هيشتغل على البرنامج: البرنامج ده إيه، بيشتغل إزاي، والكود فين.

## البرنامج ده إيه؟

برنامج كاشير وإدارة **بيشتغل من غير إنترنت** على الكمبيوتر (ويندوز ولينكس). بتبيعه **Inno Source** للمحلات والسوبر ماركت والمكتبات والمطاعم والكافيهات والشركات التجارية (جملة وتوزيع).

- **العربي هو الأساس**، ومعاه إنجليزي كامل.
- **كل نسخة بتشتغل على جهاز واحد بس** بمفتاح ترخيص بيطلعه البائع، بمدة (تجربة، شهري، سنوي، دائم).
- **التحديثات بتنزل لوحدها** من سيرفر Inno Source، وكل تحديث متوقّع بمفتاح البائع، فمحدش يقدر ينزّل تحديث مزوّر.

## مين بيستخدمه وإزاي؟

| نوع النشاط | الشاشات اللي بيستخدمها |
|---|---|
| محل / سوبر ماركت | الكاشير (باركود، ميزان، عروض، نقاط ولاء) |
| مكتبة | الكاشير + بيانات المؤلف والناشر (ISBN) |
| مطعم / كافيه | الصالة (خريطة الطاولات) + الكاشير للتيك أواي + شاشة المطبخ |
| شركة تجارية | فاتورة البيع (عميل، وحدات، خصومات، آجل) + الكاشير |

صاحب النشاط بيختار الشاشات اللي تظهر من **الإعدادات ← بيانات النشاط ← شاشات البيع**.

## أهم الأجزاء

- **المستخدمين:** 3 أدوار (مدير، مشرف، كاشير)، وصلاحيات لكل مستخدم، وموافقة مشرف بالرقم السري، وسجل نشاط بكل حاجة حساسة.
- **البيع:** كاش وفيزا ومحفظة وتحويل بنكي، والبيع الآجل بحد ائتمان، والمرتجعات، والوردية وتقرير الوردية (Z).
- **العملاء:** كشف حساب، وسندات قبض متوزّعة على الفواتير، وخصم تسوية، ودفعات مقدمة، وشيكات (تحت التحصيل، اتصرف، مرتد)، وأعمار ديون، وتذكير واتساب.
- **الأصناف:** وحدات (كرتونة/قطعة)، وقوائم أسعار، وصلاحية وتشغيلات، وسيريال، وجرد، وملصقات باركود، وأصناف بتتباع بالوزن.
- **المشتريات:** موردين، وفواتير شراء بخصم وبونص كمية، ومرتجع للمورد، واتفاقيات بونص سنوية.
- **المطعم:** طاولات، ونقل ودمج وتقسيم الحساب، وأقسام مطبخ بطابعاتها، وشاشة مطبخ على نفس الجهاز أو على تابلت.
- **الأجهزة:** طابعات حرارية و A4 وطابعة ملصقات، وميزان بيطبع ستيكر أو ميزان متوصل بالكمبيوتر.
- **الإكسيل:** رفع الأصناف والعملاء والموردين من شيت، وتنزيل الفواتير والتقارير.

## بيشتغل إزاي من جوه؟ (للمبرمجين)

- **Electron** (البرنامج نفسه) + **React** (الشاشات) + **SQLite** (قاعدة البيانات: ملف واحد على الجهاز).
- كل الحسابات والقواعد في ملف واحد: `electron/services/index.cjs`. الشاشات بتطلب منه عن طريق `api.namespace.method()`.
- **الشاشات عمرها ما بتحدد سعر أو إجمالي.** السيرفر الداخلي بيحسب كل حاجة من قاعدة البيانات.
- **الفلوس متخزنة بالقرش** (أرقام صحيحة) عشان مفيش أخطاء كسور.
- أي تعديل على شكل قاعدة البيانات بيتعمل **إضافة** في آخر قائمة `MIGRATIONS` في `electron/db.cjs`، ومينفعش نعدّل في القديم.
- كل كلمة في الشاشات لازم تتضاف بالعربي والإنجليزي في `src/i18n/ar.js` و `en.js`، والاختبارات بتفشل لو ناقصة.

التفاصيل الكاملة في `docs/ARCHITECTURE.md`، وقائمة كل ميزة ومكانها في `docs/FEATURES.md`، وقواعد الشغل في `CLAUDE.md`.

## الأوامر المهمة

```bash
cd apps/pos
npm install          # أول مرة
npm start            # تشغيل البرنامج للتجربة
npm test             # الاختبارات — لازم تكون كلها ناجحة قبل أي رفع
npm run dist:win     # عمل ملف تسطيب ويندوز محمي
npm run license -- issue --machine <كود الجهاز> --customer "اسم العميل" --days 365
```

## البيع والتفعيل والتحديثات (للبائع)

1. العميل بيسطّب البرنامج وبيبعتلك **كود الجهاز** اللي ظاهر في شاشة التفعيل.
2. إنت بتطلع له **مفتاح** من `tools/license-generator.html` أو من الأمر اللي فوق، بالمفتاح الخاص بتاعك (`pos-license-private.pem`). **أوعى ترفع الملف ده على GitHub أو تديه لحد.**
3. أي تعديل بيترفع على GitHub، وGitHub Actions بيعمل نسخة جديدة وبيوقّعها. ولما تشغّله يدوي وتختار **publish** بيرفعها على السيرفر، والبرامج المتسطبة بتحدّث نفسها.

الخطوات بالتفصيل في `docs/guide.html`.

## اللي لسه ماتعملش

- **الفاتورة الإلكترونية المصرية (ETA):** محتاجة بيانات الربط من مصلحة الضرائب، وتوكن التوقيع USB لكل شركة.
- **أكتر من فرع أو جهاز على نفس البيانات:** محتاجة سيرفر محلي أو سيرفر مركزي للمزامنة.

الخطة المقترحة لكل واحدة موجودة في آخر `docs/FEATURES.md`.
